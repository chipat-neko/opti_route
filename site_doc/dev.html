Pattern : Data / Provider / UI

Regle d'or : un screen ne fait pas de SQL direct. Il passe par un repository via un provider Riverpod. Cela rend les screens testables sans DB.

┌──────────────────────────────────────────────────────────┐
│  UI (screens/, widgets/)                                 │
│    ref.watch(xxxProvider) -> AsyncValue<T>                │
│    ref.read(xxxRepoProvider).method()                    │
└────────────────────┬─────────────────────────────────────┘
                     │
┌────────────────────▼─────────────────────────────────────┐
│  Providers (providers/)                                  │
│    final xxxRepoProvider = Provider<XxxRepo>(...);        │
│    final xxxStreamProvider = StreamProvider<List<T>>(...) │
└────────────────────┬─────────────────────────────────────┘
                     │
┌────────────────────▼─────────────────────────────────────┐
│  Data (data/)                                            │
│    XxxRepository : CRUD pur sur 1 table Drift            │
│    XxxService    : logique composee (plusieurs tables    │
│                     + APIs externes + calculs)           │
│    AppDatabase   : singleton Drift, gere migrations      │
└──────────────────────────────────────────────────────────┘

Pipeline OCR bordereaux

Le pipeline d'extraction OCR des bordereaux papier est le morceau le plus sophistique. Refactore en Sprint 1 + 2 (mai 2026) en plusieurs modules avec single responsibility.

bordereau_patterns.dart

Regex centralisees pour CP, ville, telephone, rues, tracking, etc. Source unique de verite partagee par les 3 parseurs.

110 L Voir le code →

bordereau_text_filters.dart

Helpers de rejet : isObviousLabel, looksLikeStreet, looksLikeCity, looksUnreliable (30+ labels metier observes sur les bordereaux Eure et Loir Acheminement).

226 L Voir le code →

bordereau_format_detector.dart

Detection automatique ENLEVEMENT vs LIVRAISON sur 5 cles (label majuscules, "enlever chez", "d'enlevement", etc).

41 L Voir le code →

bordereau_parser.dart

Orchestration multi-marqueurs + ciblage du gros encadre via les bounding boxes ML Kit (parseFromBlocks).

749 L Voir le code →

image_preprocess_service.dart

Bake EXIF orientation + boost contraste + auto-crop bordereau + detection de flou (variance Laplacien Sprint 2.C).

~240 L Voir le code →

client_memory_service.dart

Fuzzy match Levenshtein contre le carnet d'adresses local. Sur les clients deja livres, remplace nom + adresse OCR par les donnees validees du carnet (Sprint 2.A).

152 L Voir le code →

ocr_llm_enhance_service.dart

Edge Function Supabase + Gemini Flash pour les cas difficiles. Optionnel Free tier 1500 req/jour. PR #202 mergee mais pas encore deployee.

~150 L Voir le code →
